# BB Office 구현 인계

## 구현 범위
- jobs/*/job.json 폴더 연결과 30초 갱신, 실제 업무 배지, 질문·승인 대기 보고 동선.
- decision 필드만 쓰는 대표 결정 기록. 쓰기 전 파일 변경 여부 확인.
- 기존 직원 ID 유지, avatar/executor 구분, 직원 목록에서 API 실행 대상 파생.
- 가상 청구 입력 등록·계산·검증·결과 저장과 명시적 결정 반영.
- 입력·규칙 버전 기반 중복 방지, 입력 보존, 제한 재시도, 로컬 실행 잠금.
- 이전 결과 확정 방지, 자료 대기·검증 실패·장시간 미갱신 표시.

## 실행
Node.js 20 이상. 별도 앱 의존성 설치 없음.

```sh
npm run check
npm test
node scripts/demo-local-jobs.mjs /private/path/BB_Office_Demo
npm start
```

데모는 정상 승인 대기·단가 누락 자료 대기·합계 불일치 실패 각 1건을 만든다. 반복 실행해도 같은 입력은 중복 생성하지 않는다. 사람이 결정한 후 데모를 다시 실행하면 결정을 반영한다. 실제 회사 자료나 인증정보를 저장소에 넣지 않는다.

사용자 PC 브라우저는 클라우드 작업 폴더를 직접 선택할 수 없다. 동일 데모를 사용자 PC에서 실행하거나 가상 폴더를 복사한 뒤 jobs 폴더를 선택한다.

## 검증과 한계
- 구문 검사 및 기존·신규 테스트 합계 49개 통과.
- 주요 신규 자원의 HTTP 응답 확인.
- 실제 브라우저 UI·폴더 권한 검증은 미완료. Chromium 다운로드가 환경 네트워크 정책으로 차단됐다.
- 읽기 후 쓰기 비교는 원자적 compare-and-swap이 아니다. 다른 프로세스의 동시 수정 완전 방지를 보장하지 않는다.
- 협조하는 로컬 실행기 사이만 파일 잠금이 유효하다. 강제 종료 후 잠금 자동 회수는 없다.
- 실행 시각 미갱신은 점검 대상 표시이며 프로세스 종료를 확정하지 않는다.
- retry_pending은 예약 실행이 아니다. nextRetryAt 이후 명시적 재실행이 필요하다.
- revising은 자동 재작성하지 않는다. 수정 입력을 새 버전으로 등록한다.
- Drive·Notion API 연결과 무인 일정은 아직 구현하지 않았다. AI API 호출이나 유료 호스팅도 활성화하지 않았다.

## 다음 작업
1. 사용자가 별도 제공한 Notion 관제함을 실제로 읽어 데이터베이스·데이터 소스 ID와 속성 타입을 확인한다. 공개 문서에는 개인 데이터베이스 주소를 기록하지 않는다.
2. 작업 ID로 upsert해 중복을 막고 실행기 기록을 기준으로 상태·검증·다음 행동·점검/성공 시각을 동기화한다.
3. Notion 상태를 사람이 완료로 바꾼 것만으로 승인하지 않는다. 결정 action/note/time과 승인 대상 입력 버전을 구조화한다.
4. Drive의 허용된 가상 폴더로 읽기·결과 쓰기·버전 보존부터 검증한다.
5. 사용자 확인을 받은 일정·시간대·범위에만 스케줄을 적용한다. 실제 회사 업무의 대상·규칙·일정은 아직 미확정이다.
6. 대화용 Notion 연결은 Node 실행기의 지속 인증으로 자동 전달되지 않는다. 실제 제공되는 도구와 지원 인증 경로를 확인하며, 비밀 값은 채팅·소스에 넣지 않는다.
7. 다음 대화에 코드 실행 환경이 없다면 읽기·설계와 실제 코드 실행을 구분해 보고한다.

기존 Notes, 수동 업무 기록, 실제 회사 앱은 임의로 변경하지 않는다. 새 시스템을 중복 구축하지 않고 이 구현에 이어서 작업한다.
