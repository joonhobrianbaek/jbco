# 가상 회의 메모 정리 업무

## 사용 순서

1. BB Office 오른쪽 위 **회의 메모 정리**를 엽니다.
2. 가상 독서 모임 또는 가상 전시 예시를 선택하고 원문을 확인합니다.
3. **가상 업무 접수**를 누릅니다. 이 단계는 jobs 폴더에 요청만 저장하며 AI를 호출하지 않습니다. jobs 폴더 쓰기 권한이 필요합니다.
4. 회의 업무용 PC 실행기 ZIP을 새 폴더에 모두 압축 해제합니다. 기존 Node.js와 로그인된 Codex/Claude CLI를 사용합니다.
5. **RUN_MEETING_DEMO.cmd**를 한 번 실행합니다. 사용자 홈의 BB_Office_Demo_CLI/jobs에 접수된 가상 회의만 처리합니다. 정기 실행이나 백그라운드 서비스가 아닙니다.
6. 사이트 **작업 폴더**에서 원문, 요약, 할 일, 담당·기한, 미결정 사항과 Claude 검토를 확인합니다. 연결 중에는 30초마다 읽으며 새로고침도 가능합니다.
7. 결과가 맞으면 승인합니다. 최신 사이트에서는 추가 실행 없이 상태가 반영됩니다. 승인해도 실제 일정 등록, 메시지 전송이나 외부 제출은 없습니다.

## 오류와 재시도

- 실행 창에는 Codex 시작, 정리 완료, Claude 시작과 최종 상태가 표시됩니다.
- 실패하면 job.json의 errorSummary와 표시된 원인을 먼저 확인합니다. 완료되거나 승인 대기인 업무는 다시 모델에 보내지 않습니다.
- 원인 해결 후 실패한 회의만 다시 실행하려면 **RETRY_MEETING_DEMO.cmd**를 사용합니다. 기존 기록은 attempt-N-before.json에 보존합니다.
- 중단된 업무는 다음 실행 시 실패로 표시하고 자동으로 모델 호출을 반복하지 않습니다. 강제 종료 후 잠금이 남았다면 원래 프로세스 종료를 확인한 뒤 별도 조치가 필요합니다.

## 입력·검증 범위

- 두 가지 고정 가상 예시만 허용합니다. 자유 입력, 회사 파일 읽기, 운영 일정 연결 기능은 없습니다. 예시의 날짜와 인명은 모두 가상입니다.
- Codex는 할 일과 미결정 항목을 정리하고, Claude는 원문과 결과를 검토합니다.
- 코드는 항목 수·고유 ID·담당자·기한·원문 인용 일치와 Claude 검토 통과 여부를 별도로 확인합니다. 문장 의미의 완전한 정확성을 코드가 증명하지는 않으므로 최종 사용자 검토가 필요합니다.
- 승인 시 입력·규칙·작업 ID·결과 해시를 다시 확인합니다.

## 실행 결과 파일

- request.json: 허용된 예시와 버전의 접수 정보
- job.json: 현재 상태·이벤트·검증·사용자 결정
- codex-result.json: 요약·할 일·미결정 항목
- claude-review.json: 원문 대조 검토 결과

## 검증

개발 환경에서 주입한 가짜 CLI 응답으로 새 테스트 8개와 전체 테스트 87개를 통과했습니다. 담당·기한·근거 변조, 중복 항목, 검토 거절, 승인 무결성, 중복 접수, 재실행 방지, 동시 실행 잠금과 중단 처리 등을 확인했습니다.

이 개발 환경에서는 실제 두 CLI를 실행하지 않았습니다. 앞선 가상 인보이스 업무의 Windows 호출 성공은 확인했지만 이번 회의 업무의 실제 모델 응답 형식과 Windows 실행은 별도 확인이 필요합니다. 브라우저 화면 점검도 환경 접근 제한으로 미검증입니다.

Notion에는 이 기능의 구현·검증·배포 기록을 대화의 세션 기록에 저장합니다. PC에서 생성되는 개별 회의 결과가 Notion에 자동 업로드되는 기능은 연결하지 않았습니다.
